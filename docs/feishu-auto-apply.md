# 飞书系校招无人值守投递流程（两阶段投递法）

> 适用对象：使用飞书招聘系统（jobs.feishu.cn 系列域名，含各公司独立 portal）的校园招聘官网。
> 本文档描述一种**半自动**投递方法：在完成一次性人工登录后，可实现"批量职位识别 + 自动提交简历"的无人值守流程。
> 与主 README 的合规立场一致：**不自动注册、不自动建账号**；仅复用用户已登录的会话完成提交。

## 背景：飞书系的两个关键特性

1. **登录态不跨 portal 共享**：每家公司在 jobs.feishu.cn 下有独立子域名（如 `xxxx.jobs.feishu.cn`）。在 A 公司 portal 登录的 cookie 不能用于 B 公司 portal，每个 portal 需单独登录。
2. **简历表单数据是账号级共享**：登录任一 portal 后，教育经历/实习经历/项目经历等简历数据在**所有 portal 间复用**。即：登录过一次、填过一次，后续任何 portal 提交时表单自动带出全部数据——这是"无人值守批量投递"可行的根基。

3. **登录方式**：大多数 portal 仅支持「手机号 + 短信验证码」（无邮箱选项）；部分支持邮箱验证码。短信验证码需用户在真实浏览器/人工配合获取。

## 两阶段投递法（核心）

### 为什么需要两阶段

- 有登录态的会话访问职位列表页时，页面会重定向到**精简视图**（仅显示公司名/岗位数量/账号手机号脱敏），职位列表不渲染 → 拿不到职位 ID。
- 无登录态的会话能正常渲染职位列表，但提交简历必须登录。

解法：把「拿职位 ID」和「提交简历」拆成两个独立阶段：

```
阶段一（无需登录）：
  无 cookie 的无痕 context 打开 portal 的职位列表页
  → 用 page.on('response') 拦截页面内部请求的 API 响应
  → 解析 JSON 中的 job_post_list，提取 { id, title } 映射表

阶段二（需要登录态）：
  带 cookie 的持久化 context 直接 goto `resume/{postId}/apply`
  → 等待表单自动填充（账号级共享数据，约 10-15s）
  → 补齐少量必填项（如意向城市）
  → 点击「提交简历」
  → 校验是否出现「感谢你的投递」成功提示
```

### 关键实现要点

| 要点 | 说明 |
| --- | --- |
| API 拦截而非主动 fetch | 直接 `fetch('/api/v1/search/job/posts')` 会返回 HTML（需要正确 referer/session）；改为拦截页面自然发出的请求更可靠 |
| 等待策略 | 职位列表页用 `domcontentloaded` + 固定等待，不要用 `networkidle`（SPA 长轮询会导致超时） |
| 登录态持久化 | `launchPersistentContext(profileDir)` 保存 cookies，跨天有效（实测约 2 天） |
| 表单校验 | 提交前**不要**点击「添加」展开板块（会插入空行导致校验失败）；仅当岗位明确要求额外字段（如项目链接）时单独补齐 |
| 限投校验 | 提交前调用 limit_check 类接口可查询该账号在该公司的投递次数上限 |
| 意向城市 | 部分表单需手动选择意向城市，用原生 setter + input 事件模拟填写 |

### 批量投递脚本骨架（伪代码）

```
node feishu_batch.js <portal域名> <postId1> [postId2...]

流程：
1. 读取持久化登录态 cookies（JSON 文件）
2. context.addCookies(cookies)
3. 对每个 postId：
   a. goto https://{portal}/resume/{postId}/apply
   b. waitForTimeout(15000) 等表单自动填充
   c. 如有意向城市字段 → 选择
   d. 点击「提交简历」
   e. 断言出现「感谢你的投递」→ 记录成功；否则记录失败原因
4. 输出投递结果清单
```

## 实操经验（踩坑记录）

1. **登录后职位列表不渲染** → 用两阶段法绕过（见上）。
2. **验证码自动发送被风控**：headless 环境下点击「获取验证码」可能被静默拦截（按钮无变化、手机收不到码）。此时需用户在真实浏览器手动触发。
3. **多浏览器实例并行会 timeout**：同一脚本内多次 `launch()`/`launchPersistentContext()` 会资源争抢。一次只跑一个浏览器实例，需要并行时拆成多个脚本顺序执行。
4. **同一家公司投递数量**：同一账号在一家公司建议不超过 2-3 个匹配岗位，避免海投导致被拉黑。部分公司有硬性上限（如仅 1 个且不可修改、限 2 个志愿等），提交前务必核实。

## 合规与安全提醒

- 仅在用户本人明确授权的账号与流程中使用；不自动注册、不自动建账号。
- 登录态 cookies 属敏感信息，只保存在本地工作区，**不要提交到公开仓库**（.gitignore 应排除）。
- 每家公司的投递规则（限投数量/是否可修改）以官网为准，提交前核实。
